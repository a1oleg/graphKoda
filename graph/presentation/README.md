# Единое пространство аннотатора и презентера

## Отдельное окно записи

Запуск: `powershell -NoProfile -File dev/startPresenter.ps1` из coldKode.
Окно `coldKode PRESENTATION` использует собственный user-data и пустой каталог
расширений в `tmp`. Graph Explorer запускается из исходников; draw.io открывается
в его встроенной панели. Чат и настройки основного окна не копируются.

Презентер и `dev/demoStep.mjs` используют только порт **17844** и отдельный
`tmp/graph-presenter-token.local`. Основное окно остаётся на 17843. Нет fallback
в окно чата: закрытое демонстрационное окно даёт ошибку.

В репозитории presenter выполните `node scripts/bind_presenter_obs.mjs`:
единственный включённый источник «Захват окна» будет привязан к точному заголовку
демонстрационного окна. Кадрирование сохраняется, прежние настройки записываются
в `output/obs-presentation-*/previous-settings.json`. Если окно закрыто, OBS не
должен подставлять другое окно Code. Не сворачивайте окно записи: захват Windows
может перестать обновлять свёрнутые окна. Работать в окне чата поверх него можно.

После изменения модуля презентера перезапустите оркестратор, чтобы GraphQL
использовал новый адрес моста.

`POST http://127.0.0.1:8791/api/graphql` принимает `query`, `variables`,
`operationName`. `GET /api/graphql/schema` возвращает SDL. Старый адрес
`/api/annotations/graphql` сохранён как совместимый вход в ту же схему.

Общая сущность — `CodeEntity`, адресуемая парой **профиль базы + stableId**.
Она предоставляет факты Neo4j, связанные через `HAS_ANNOTATION` аннотации
и представления в зарегистрированных диаграммах. `cellId` уточняет визуальное
представление, но не заменяет идентификатор кода.

`AnnotationPlanNode.entity(profile: ...)`, `AnnotationWorkItem.entity(...)`
и `ValueOriginTask.entity(...)` ведут к этой же сущности. Профиль нужно указать
явно и согласовать с базой задания аннотатора: одинаковые stableId в разных
базах не доказывают одинаковую версию кода. Это не миграция аннотатора в Aura.

## Представления Фишера

Реестр `views.json` связывает:

- `fisher-functions`: высокоуровневый граф `graph/draw/scenes/fisher.drawio`;
- `fisher-flow`: полную `graph/draw/generated/Fisher-Yates.drawio`;
- `fisher-detail`: адресно раскрываемый граф `graph/draw/scenes/fisher-detail.drawio`.

Все три используют реальные stableId из профиля `aura`. В полной диаграмме
`getRandom` соответствует `f1-block`, `swap` — `f2-block`. Фокус умеет раскрыть
свёрнутых родителей и подобрать масштаб по геометрии целевого блока.
Указка — временный слой редактора: не меняет граф и не ищет пиксели на скриншоте.
При смене модели или масштаба указки убираются, чтобы не оставались ложные цели.

## Сценарии

Операции находятся в `fisher.graphql`, переменные — `fisher.variables.json`.
Сначала выполните `Validate`, затем `Play` с теми же переменными. Полученный
`runId` передавайте в `InspectRun`. Сценарий переключает три представления,
показывает реализацию вложенных функций и последовательно открывает сниппеты.
Время пока демонстрационное, не синхронизировано с озвучкой.

Действия: `OPEN`, `FOCUS`, `POINTER`, `EXPAND`, `HIDE`, `MOVE`, `ANNOTATIONS`.
Также `OPEN_CODE` открывает файл и выделяет диапазон по `stableId` в группе
справа (`placement: RIGHT`) или снизу (`placement: BELOW`) от диаграммы.
Пример: `fisher-code.variables.json`; используется операция `Play` из `fisher.graphql`.
Группы, созданные этим контроллером, переиспользуются; пользовательские вкладки
не закрываются. Файл разрешается только внутри корня инструментария или исходников,
неоднозначный путь и устаревшие координаты отклоняются. Нужна версия расширения 0.0.427+.
`EXPAND` требует явных направления, типов связей и целевых stableId; связь
проверяется в Neo4j. `MOVE` использует дробные координаты draw.io.
`presentationNeighbors` помогает выбрать реальные связи, `presentationScene`
читает сохранённые координаты сцены. Для FLOW раскладка не переписывается.

`atMs` — не раньше указанного момента. Каждый шаг ждёт подтверждения UI;
опоздавшие шаги не пропускаются. Одновременно исполняется один сценарий.
`controlPresentation(runId: ..., action: PAUSE|RESUME|CANCEL)` управляет прогоном;
уже отправленная UI-команда завершается, следующая ждёт. Ошибка останавливает
прогон и остаётся в `presentationRun.error`.

Перед показом сохраните редакторы. Нужна обновлённая версия расширения и
перезагрузка окна VS Code. Открываются только зарегистрированные файлы из
`graph/draw`; мост требует локальный токен, произвольных команд/eval нет.

## Границы ответственности

GraphQL описывает запросы и запуск. Порядок, ожидания и движение исполняет
сценарный движок, а не правила выполнения полей GraphQL.
Сниппеты Фишера помечены `authored-scene-snippet`: это заготовки рассказа,
не результаты реально выполненного аннотирования. Показ их не пишет в Neo4j.
Автоматическое превращение событий аннотатора в сценарий пока не реализовано.

Журнал и проверенный план сохраняются в `tmp/presentation/<runId>.json`.
Прогоны доступны API в памяти процесса; после перезапуска они не возобновляются.
Проверяются хеши диаграмм перед стартом, но это не механизм полного снимка
и отката. Повторный запуск начинает с текущих файлов; сценарий Фишера явно
сбрасывает видимость сниппетов и выбранной детальной ветви.
