# Управление демонстрацией

## Перезагрузка окна презентации

`node dev/reloadPresentation.mjs` вызывает защищённую токеном команду
`POST /demo/step` с `{ "surface": "window", "action": "reload" }` на порту 17844.
Команда доступна с версии 0.0.430 только в окне презентации, отклоняется при
несохранённых документах или незавершённом шаге. Основное окно не перезагружается.
Скрипт подтверждает завершение по новому PID хоста и новому токену, а не только
по ответу `reload-scheduled`. Первичная активация новой версии требует обычной
перезагрузки; последующие перезагрузки выполняются этой командой.

Версия 0.0.420 добавляет `graphKodaGraphExplorer.demoStep` и локальный `POST /demo/step` на порту 17843. Это управление настоящими меню и панелью, не нарисованная имитация и не произвольное выполнение JavaScript.

После установки выполнить **Developer: Reload Window** и заново открыть диаграмму, чтобы обновился её плагин. Несохранённые изменения предварительно сохранить. Держать открытой одну диаграмму нужной функции: при нескольких одинаковых экземплярах команду заберёт первый ответивший.

Токен создаётся при активации в `tmp/graph-demo-token.local` и меняется после перезапуска. Не копировать его в сценарии, таблицы или Git. `dev/demoStep.mjs` читает его самостоятельно.

Сохранить один шаг в JSON и вызвать из корня проекта:

```powershell
node dev/demoStep.mjs --file tmp/demo-step.json
```

Пример открытия настоящего ПКМ на цикле текущей диаграммы Фишера:

```json
{
  "surface": "diagram",
  "action": "contextMenu",
  "functionStableId": "examples/fisher-yates/src/shuffle.ts:6:7:36:1",
  "cellId": "f0-n4"
}
```

ID зависят от текущего кода/диаграммы, это не исключения в алгоритме. Актуальные корень и цикл — в `tmp/fisher-yates/runtime/latest.json`, cellId — в файле диаграммы. Вместо cellId можно передать stableId, но несколько совпадений вызовут ошибку, а не случайный выбор плитки.

Шаги выполнять последовательно, ожидая ответ каждого:

| surface | action | Дополнительные поля | Подтверждение |
|---|---|---|---|
| diagram | contextMenu | cellId либо stableId | Меню открыто, возвращён список его пунктов |
| diagram | menuClick | label — точный текст пункта | Штатный обработчик пункта вызван |
| diagram | dismissMenu | — | Меню закрыто |
| runtime | waitForAnalysis | необязательный sessionId | Загружена статистика нужной функции, возвращены cases/segments |
| runtime | selectCase | index — исходный индекс случая, с нуля | Видимая строка выбрана штатным кликом |
| runtime | selectSegment | id из результата waitForAnalysis | Нажат штатный переключатель сегмента |
| runtime | selectAll | — | Нажат «Все» |

`functionStableId` обязателен в каждом шаге. `sessionId` в runtime-командах проверяет выбранный прогон, но не переключает его автоматически. После фильтрации невидимый случай не выбирается: сначала selectAll. Команды не регенерируют диаграммы и не запускают новые случайные прогоны.

Для меню статистики передать `label: "показать статистику Цикла"`. Затем вызвать `waitForAnalysis`, после него — selectCase/selectSegment. Открытие меню и выбор пункта разделены, чтобы между ними можно было показать меню во время озвучки.

Подтверждение menuClick означает вызов обработчика, а не завершение асинхронной операции. Подтверждение runtime-клика означает выбор строки/сегмента в панели; отрисовка подсветки в другом webview происходит через существующий bridge и пока не имеет отдельного подтверждения. Не выдавать эти ответы за гарантию записанного кадра. Автоматическая видеозапись и привязка действий к таймингам речи — следующий слой, здесь не запускаются.

Проверка на реальных файле Фишера, редакторе и runtime-данных:

```powershell
node dev/checkFisherDemoControl.mjs
```

Проверка не меняет диаграмму и не делает скриншотов. Она изолирует транспорт VS Code, но использует настоящий popup draw.io, production HTML панели и реальный записанный прогон. Для неё нужен запущенный runtime relay на 8787.
